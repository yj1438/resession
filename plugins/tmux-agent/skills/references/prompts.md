# Agent 消息信封

使用能让意图和授权边界无歧义的最小信封；先替换占位符，不要把尖括号占位符原样发送。信封前缀 `CALLER` 代指调用侧 Agent，不限定其实现。将 `<TARGET>` 替换为 `CLAUDE` 或 `CODEX`；Claude 仍得到原有 `[CALLER→CLAUDE]` 前缀。每个实际信封加入约束：由接收方直接处理并回传，不再委派其它 Agent。

## 快速 Ping

```text
[CALLER→<TARGET>][PING]
hello。请简短回复确认收到。
```

## 咨询

用户说“问问 目标 Agent”“让 目标 Agent 看一下”或征求第二意见、但未授权实施时，默认使用本信封。

```text
[CALLER→<TARGET>][CONSULT][READ_ONLY]
工作目录：<工作区绝对路径>
目标：<问题或决策>
已知上下文：<仅必要事实>
约束：只分析，不运行命令，不修改文件，不进行外部操作。
期望输出：结论、关键依据、主要风险；缺少信息时明确指出。
```

## 代码评审

```text
[CALLER→<TARGET>][REVIEW][READ_ONLY]
工作目录：<工作区绝对路径>
评审对象：<文件、commit 或 diff 描述>
关注点：<correctness/security/regression 等>
约束：只读评审，不修改文件，不提交代码，不扩展范围。
期望输出：只报告高置信问题，按严重程度排序，并给出文件和行号；没有问题时明确说明。
```

## 已授权实现

仅在用户已授权修改文件时使用。

```text
[CALLER→<TARGET>][TASK][WRITE_ALLOWED]
工作目录：<工作区绝对路径>
目标：<具体成果>
允许修改：<精确的文件/目录或范围>
禁止事项：不删除文件，不修改全局配置，不提交或推送，不部署，不进行范围外操作。
验收方式：<测试/检查>
完成后输出：修改文件、验证结果、遗留风险。
```

若所需操作超出已授权范围，目标 Agent 必须停下并上报，不得自行假定已获许可。

## 状态查询

```text
[CALLER→<TARGET>][STATUS][READ_ONLY]
请只回复：当前状态、已完成内容、正在进行的步骤、是否需要用户输入。不要启动新工作。
```

## 任务移交

```text
[CALLER→<TARGET>][HANDOFF]
目标：<共同目标>
调用方已完成：<事实与产物>
请 目标 Agent 负责：<有边界的子任务>
共享约束：<授权与安全边界>
期望回传：<交付物与验证证据>
```

## 超时追问

不重发原任务。确认 目标 Agent 已空闲或上一轮已失败后，发送：

```text
[CALLER→<TARGET>][STATUS][READ_ONLY]
上一条请求尚未收到最终回复。请说明它仍在执行、已经失败，还是需要补充信息；不要重复执行可能产生副作用的操作。
```
